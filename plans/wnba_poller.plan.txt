- Capturing a Sheet thought does not rewrite `path210.md`. An explicit
  receptionist generation/edit/delete/undo request invokes the validated skill

Thought entry:

- Support both Telegram and direct Sheet entry.
- Preserve each thought as a new append-only row with UTC and Eastern
  timestamps.
- Never overwrite an earlier thought merely because a later opinion changes.

Schedule:

- Maintain a rolling next-14-days view.
- Refresh it once daily from the proven ESPN WNBA schedule code.
- Preserve user-editable Sheet fields during machine upserts.
- Store UTC internally and display Eastern time.

Odds:

- BetOnline only for the first version.
- Full-game moneyline, spread, and total.
- First-half spread and total.
- Poll hourly while a game is more than six hours from tip.
- Poll every 15 minutes from six hours before tip until commence time.

  market -> side -> exact reasoning.

6. POLLING AND QUOTA DESIGN
---------------------------

Run a lightweight systemd timer every 15 minutes. The scheduled command reads
`wnba_games` and exits without an Odds API call unless at least one game is due.

For each upcoming game:

- more than six hours to tip: due if no successful poll in the last hour
- six hours or less to tip: due if no successful poll in the last 15 minutes
- at or after tip: not due

When any game is due:

1. Use one bulk WNBA odds request for full-game `h2h,spreads,totals`.
2. Use event-specific requests only for due event IDs and request
   `spreads_h1,totals_h1`.
3. Merge full-game and first-half results by Odds API event ID.
4. Upsert opening/latest game state.
5. Append deduplicated/hourly snapshots.
6. Record request quota headers and surface low quota as a service warning.

This is cheaper than requesting all five markets separately for every event.
Missing first-half markets are stored as `nodata`, not treated as a failed poll.


7. TELEGRAM EXPERIENCE
----------------------

Run a separate private Bot API process as `@wnbaguesser_bot`:

- `/wnba` - browse the next 14 days of WNBA games in Eastern time
- `/wnba_thoughts` - show recent append-only thought/lean submissions
- `/wnba_cancel` - cancel the active selection/reasoning flow

Flow:

1. User taps a game.
2. Bot shows opening/latest full-game and first-half BetOnline lines.
3. User selects full game or first half.
4. User selects a valid market (full: spread/moneyline/total; H1:
   spread/total).
5. User selects a team side or over/under.
6. Bot uses ForceReply to request exact reasoning and any line/price where the
   preference changes.
7. The reply is appended exactly to `wnba_thoughts` with structured selection
   fields and frozen current lines.
8. Confirmation includes matchup, selection, and Eastern timestamp, with an
   `Add another update` button that refreshes lines and appends another row for
   the same selection.

Guardrails:

- Every command, callback, and text handler requires a private chat and checks
  the numeric user ID against the WNBA-only Sheet allowlist before game/thought
  access. The bot refuses to start with an empty allowlist.
- The allowlist is seeded idempotently with the approved user during workbook
  initialization and is cached for no more than 60 seconds at runtime.
- Callback data contains only short action tokens and bounded immutable event
  identifiers and stays below Telegram's 64-byte limit.
- In-flight state belongs to the authorized user, expires after 15 minutes, can
  be cancelled, and is intentionally in memory like the NFL v1 flow. A process
  restart drops the transient selection; the user reruns `/wnba`.
- Telegram message identity makes retries idempotent.
- Thought text is written as raw cell text and never interpreted as a formula.
- Sheet failures are visible and retain the original exact text/submission ID
  in the active flow so the same reply retries safely.
- User thought capture never grants root/Git access or changes `path210.md`
  automatically.

Both Telegram surfaces expose `View game leans` after game selection. The
default view is:

1. latest active Claude lean revision, if any
2. chronological user thought/lean history from `wnba_thoughts`

A separate `Revision history` action shows superseded and deleted Claude
revisions with revision IDs, timestamps, and commit links/SHAs. Both views use
the same deterministic Sheet history reader so the bots cannot disagree about
which revision is active.

Receptionist Claude-generation flow:

1. Existing private-chat/numeric-user authorization runs before WNBA state,
   Sheet, template, skill, or Git access.
2. User invokes the WNBA lean command/flow and selects an upcoming game with
   buttons.
3. Receptionist reloads the selected immutable event ID from current
   `wnba_games`, displays the current matchup/lines/history summary, and shows
   exactly two generation actions:
   - `Generate now using standard template`
   - `Copy template text`
4. Generate now constructs the standard normalized request and invokes the
   common generation entry point directly.
5. Copy template sends copyable plain text in this shape:

       WNBA_LEAN_REQUEST_V1
       event_id: <immutable event ID>
       matchup: <away team> @ <home team>
       request: generate using standard template
       additional_thoughts:

6. The user may paste that text into the normal receptionist message box,
   append or edit `additional_thoughts`, and send it like an ordinary message.
   A deterministic parser recognizes the marker before generic Claude prompt
   queuing and routes it to exactly the same normalized generation entry point
   as Generate now.
7. The parser treats event ID as authoritative but still reloads current Sheet
   state. The supplied matchup must equal the current event matchup after
   normalization; stale, missing, ambiguous, started, or mismatched games fail
   visibly before Claude or Git runs. User-authored extra thoughts remain
   request context, not authoritative state.
8. The skill generates and persists one revision, then returns the active lean,
   revision ID, validation result, and Git commit SHA to the receptionist.

Claude output defaults:

- full-game side lean
- full-game total lean
- first-half side and/or total only when current/history evidence supports a
  meaningful lean
- strength/confidence for each emitted lean
- explicit watch/change conditions tied to lines, prices, injuries, timing, or
  missing data
- no forced first-half opinion and no invented market/state when evidence is
  weak

Natural-language follow-ups in the receptionist may edit or delete a prior
Claude lean. The receptionist resolves the requested event/revision
deterministically, shows the intended operation when ambiguous, and invokes the
same skill with `revise` or `delete`. `Undo latest` appends a restoration
revision and a new Git commit; it never rewrites Git or Sheet history.

8A. CLAUDE LEAN SKILL AND DETERMINISTIC WORKFLOW
------------------------------------------------

Add a reusable Claude Code skill at
`.claude/skills/wnba-lean/SKILL.md`. Both Generate now and recognized pasted
templates invoke this same skill entry point; natural-language edit/delete/undo
requests resolve to the same operation model.

Skill responsibilities:

1. Receive a normalized operation (`create`, `revise`, `delete`, or `undo`) and
   immutable event/revision identifiers from the receptionist.
2. Load the selected current game, normalized opening/latest snapshots,
   historical snapshots, every Sheet user thought, and effective Claude
   revision history.
3. Read `path210.md` rules, the matching event block, model cache,
   precedents/continuations, and only the relevant historical sections selected
   by deterministic extractors.
4. Produce structured JSON for full-game side/total and optional first-half
   side/total, including strength, evidence, watch/change conditions, and cited
   source revision/snapshot IDs.
5. Hand structured output back to deterministic helpers; Claude does not edit
   Markdown, Sheets, or Git directly.
6. Return the published revision ID and commit SHA, or a specific failure with
   no success-shaped fallback.

Deterministic-first helper design:

- `game resolve`: validate event ID, matchup, status, timing, and unique current
  Sheet row.
- `context build`: fetch/normalize opening/latest/history and all thoughts;
  extract relevant `path210.md` rules/cache/precedent/continuation sections.
- `request parse`: normalize both button generation and
  `WNBA_LEAN_REQUEST_V1` pasted text into one request schema.
- `output validate`: enforce emitted market/side schema, supported periods,
  required strength/watch fields, source IDs, and no invented lines.
- `path apply`: deterministically append/revise/delete/undo only the correct
  immutable event block; no free-form search-and-replace by Claude.
- `path validate`: parse the resulting document, enforce one active block per
  event/revision chain, required markers, stable ordering, and unchanged
  unrelated blocks.
- `revision append`: write immutable Sheet revision/publication events with
  `RAW` input and idempotency keys.
- `git publish`: acquire a workflow lock; require clean `www/main`, HEAD equal
  to `origin/main`, expected base SHA, no unrelated diff, and one-event scope;
  create exactly one auditable commit and push `main`.
- `undo/edit/delete`: resolve exact revision chains and produce append-only
  Sheet events plus deterministic path changes; never rewrite Sheet rows or Git
  history.

Claude reasoning chooses and words the lean. Python owns lookup, IDs, state,
text placement, validation, Sheet writes, Git preconditions, commit creation,
push, and recovery.

Successful create/revise/delete/undo sequence:

1. Acquire the per-repository/per-event lock and verify Git/Sheet preconditions.
2. Build deterministic context and ask Claude for structured output.
3. Validate the structured output.
4. Deterministically apply the event-block change to `path210.md`.
5. Append an idempotent Sheet revision event with content hash, intended
   active/superseded/deleted result, and expected Git base.
6. Run full path/document/diff validation.
7. Create exactly one commit with event ID and revision ID in the message.
8. Push that commit to `www/main`.
9. Append a publication receipt event containing the resulting commit SHA.
10. Return success only after the pushed SHA and receipt are confirmed.

`wnba_lean_revisions` therefore stores append-only records of type
`revision`, `publication_receipt`, or `abort_receipt`. Readers consider a
revision effective only when it has a matching successful publication receipt.
If validation, commit, or push fails after the initial revision event, helpers
restore the working tree when safe, append an abort receipt linked to the
revision, preserve the prior active revision, and report failure. This avoids
updating history in place or displaying an unpublished lean as active.

Git and deployment boundaries:

- Generating, revising, deleting, undoing, committing, and pushing
  `path210.md` is approved coding work, not a production service deployment.
- The skill may push one validated lean commit without a deployment approval.
- It may not deploy/restart/install the poller, Guesser, receptionist, systemd
  units, or environments.
- Any production service deployment still requires the existing immutable
  Telegram deployment request and explicit approval.

12. IMPLEMENTATION RECORD
-------------------------

Implementation date: 2026-08-05

Implemented in `apps/wnba-poller`:

- Python 3.12 package, CLI, README, offline tests, root-only installer, and
  hardened systemd service/timer artifacts.
- Byte-exact copies of every approved non-secret source artifact, plus an
  active byte-exact `path210.md` copy. No environment/key file was copied.
- One ESPN range request for the Eastern-date rolling 14-day window. Parsing
  stores UTC plus Eastern timestamps, and schedule writes are upsert-only. A
  request or response-shape failure occurs before any Sheet write.
- Clear normalized columns rather than the NFL packed strings. Opening fields
  retain their first available value; latest fields update on each successful
  poll. A missing first-half market is represented as `nodata`.
- Due decisions use `last_odds_polled_at`: hourly when more than six hours from
  tip, every 15 minutes at or inside six hours, and never at/after tip. The
  scheduled code returns before constructing an Odds API client when no game is
  due.
- One bulk BetOnline `h2h,spreads,totals` request followed by
  `spreads_h1,totals_h1` event requests only for matched due games.
- Immediate changed snapshots and 60-minute identical snapshots, including the
  latest Odds API used/remaining headers.
- Direct-Sheet reconciliation reads formula text and rewrites the completed row
  with `RAW` input, preserving exact thought text while neutralizing formula
  execution. Rows with an existing thought ID are immutable/idempotent.
- `SheetsStore.append_thought_record(...)` freezes Telegram identity,
  structured period/market/side, selected opening/latest price, and all current
  normalized lines. It deduplicates on immutable thought ID or Telegram
  chat/message identity and writes with `RAW` input.
- Added `wnba_allowed_users`, a WNBA-only numeric Sheet allowlist. Workbook
  initialization can idempotently seed the approved user, and the bot refuses
  startup when the allowlist is empty.
- Workbook initialization is non-destructive by default. Replacing WNBA tabs or
  removing the copied NFL tabs requires `--confirm-replace-tabs` and a new JSON
  backup path.
- The odds/thought cycle and daily schedule sync share one nonblocking systemd
  lock and run as `receptionist-agent`, with 96 MB `MemoryHigh` and 160 MB
  `MemoryMax`.

Implementation boundaries:

- Automated legacy text-history import was not added. The preserved log has no
  immutable event IDs or absolute capture timestamps, so an unreviewed import
  could attach repeated fixtures to the wrong event.

Dedicated Telegram intake implementation:

- The previously considered receptionist commands and JSON/sudo bridge are
  superseded and were removed. No receptionist source, database, sudoers, or
  deployment artifact is changed by this WNBA scope.
- Added standalone `wnba-guesser-bot` for `@wnbaguesser_bot`, using the Telegram
  Bot API with only its dedicated token. Runtime verifies the token username.
- Added the NFL-style game -> period -> market -> side -> ForceReply reasoning
  flow. Full game exposes spread/moneyline/total; first half exposes
  spread/total. Opening and latest values are shown at each relevant step.
- Every command/callback/text update is private-chat only and checks the
  WNBA-only numeric Sheet allowlist before game or thought access. The allowlist
  cache lasts at most 60 seconds.
- Exact reasoning is never stripped before `RAW` append. The deterministic
  `telegram:<chat_id>:<message_id>` identity makes Telegram retries
  idempotent. An unconfirmed write retains the original text/identity in the
  active flow for a safe same-text retry.
- Successful submissions keep the structured selection available through
  `Add another update`; the bot refreshes current lines and appends a new row.
  Earlier rows are immutable. `/wnba_thoughts` lists recent rows and
  `/wnba_cancel` clears the active flow.
- Selection state is deliberately in memory, matching the proven NFL v1
  trade-off: it expires after 15 minutes and a service restart requires
  `/wnba` again. Durable opinions live in Sheets, not process state.
- Added a dedicated mode-0600 env path and hardened
  `wnba-guesser-bot.service`. It runs as `receptionist-agent` from the same
  root-owned WNBA venv, with independent restart and 128 MB/192 MB memory
  limits. The root installer can explicitly enable timers and/or the bot.
